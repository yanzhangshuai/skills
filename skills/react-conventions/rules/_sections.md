# 分节

本文件定义所有分节、它们的顺序、影响等级与说明。
分节 ID（括号内）是规则文件的**文件名前缀** —— `state-` 开头的文件都属于第 1 节。

分节之间按编号排序；**分节内部**按规则 frontmatter 里的 `order` 排
（没写 `order` 就按标题排）。所以 `order` 表达的是「同节内该先讲哪条」。

顺序即优先级：AI 拿不准先守哪条时，**按编号从小到大**。

---

## 1. 状态语义 (state)

**影响：CRITICAL**
**说明：** 进行中状态的名字决定了读代码的人能不能一眼分清「在读」还是「在写」。
名字错了，整份代码的异步路径都要靠注释才能读懂 —— 而这是每一条后续规则的底座。

## 2. 异步动作 (action)

**影响：CRITICAL**
**说明：** 每个异步动作都手写一遍 `setPending` / `try` / `catch` / `finally`，
必然出现漏清错误、漏解 pending、错误文案各写各的。统一外壳是消除这类重复的唯一办法。

## 3. 错误处理 (error)

**影响：CRITICAL**
**说明：** 错误显示的位置错了，用户填了半天的表单会连人带内容一起消失。
这是唯一一条「做错了用户直接骂人」的规则。

## 4. 目录与边界 (layout)

**影响：HIGH**
**说明：** 代码放错地方不会立刻报错，但会让「这个字段后端叫什么」「这个逻辑在哪」
只能靠全局搜索回答。重构时最先漏掉的就是这些。

## 5. 命名 (naming)

**影响：HIGH**
**说明：** 文件名与标识符的约定本身不改变行为，但它决定了搜索能不能用、
import 排序会不会天天打架、类型提示读不读得懂。

## 6. 逻辑抽离 (extract)

**影响：MEDIUM**
**说明：** 抽早了多一跳，抽晚了页面变泥球。这节给的是**可判断的触发条件**，
不是审美偏好。

## 7. React 19 边界 (react19)

**影响：MEDIUM**
**说明：** React 19 的新 API 很容易被误用成它的「近亲」。这里划清 `use()` 的适用范围 ——
它只能读，不能替代动作 hook。

## 8. 代码格式 (format)

**影响：MEDIUM**
**说明：** 本项目当前**只配了 `tsc --noEmit`，没有 ESLint / Prettier**，
所以格式没有机器兜底。这一节只写「工具查不出来、必须靠约定」的那部分 ——
导入的分组与顺序。引号 / 分号这类能 `--fix` 的，不写进规范。
